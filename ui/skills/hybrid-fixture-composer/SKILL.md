---
name: hybrid-fixture-composer
description: "Use when generating the single Playwright fixture file that exposes both api clients and page objects to specs, enabling hybrid API + UI end-to-end tests."
---

# Goal
Emit one file — `api/fixtures/hybrid.fixture.ts` — that becomes the **only** entry point hybrid specs import from. It must:

1. Extend Playwright's `base` test with two grouped fixtures: `api` and `pages`.
2. Instantiate every generated API client class once per test using the built-in `request` fixture.
3. Instantiate every existing Page Object class once per test using the built-in `page` fixture.
4. Re-export `expect` so specs need only one import.

# Inputs
- `client_files` — array of `{ file_path, domain }` from `api-client-generator`
- `page_class_files` — array of `{ file_path, page_name }` from `ui-build-tests-from-ado`
- `test_output_path`
- `api_auth_strategy` — used to decide whether to apply `storageState` in the fixture

# Generation Rules

- Import every client by its class name (`<Domain>ApiClient`) from `../clients/<domain>.client`.
- Import every page class by its class name (`<PageName>Page`) from `../../pages/<page>.page`.
- Import `config` from `../../config/test-config`.
- Build two TypeScript interface types `ApiFixtures` and `PagesFixtures` listing the grouped members.
- The `api` fixture creates one record keyed by the camelCased domain name; each value is a `new <Domain>ApiClient(request, config.apiBaseUrl)`.
- The `pages` fixture creates one record keyed by the camelCased page name (drop the `Page` suffix); each value is a `new <PageName>Page(page)`.
- Re-export `expect` from `@playwright/test`.
- No business logic in the fixture — only construction.

# Template

```typescript
// api/fixtures/hybrid.fixture.ts
// Auto-generated by ui-build-api-layer.
// Single entry point for hybrid API + UI specs.
import { test as base } from '@playwright/test';
import { config } from '../../config/test-config';

// --- API clients ---
import { TenantApiClient } from '../clients/tenant.client';
import { UserApiClient }   from '../clients/user.client';

// --- Page objects ---
import { LoginPage }    from '../../pages/login.page';
import { TenantsPage }  from '../../pages/tenants.page';

type ApiFixtures = {
  api: {
    tenant: TenantApiClient;
    user:   UserApiClient;
  };
};

type PagesFixtures = {
  pages: {
    login:   LoginPage;
    tenants: TenantsPage;
  };
};

export const test = base.extend<ApiFixtures & PagesFixtures>({
  api: async ({ request }, use) => {
    await use({
      tenant: new TenantApiClient(request, config.apiBaseUrl),
      user:   new UserApiClient(request, config.apiBaseUrl),
    });
  },
  pages: async ({ page }, use) => {
    await use({
      login:   new LoginPage(page),
      tenants: new TenantsPage(page),
    });
  },
});

export { expect } from '@playwright/test';
```

# Hybrid Spec Pattern (reference only — emitted by `ui-build-api-layer` when `emit_hybrid_spec_stubs` is true)

```typescript
import { test, expect } from '../api/fixtures/hybrid.fixture';

test('user sees newly provisioned tenant in selector', async ({ api, pages, page }) => {
  // ARRANGE (api)
  const tenant = await api.tenant.createTenant({ name: 'AGC-QA01' });

  // ACT (ui)
  await pages.login.goto();
  await pages.login.fillUsername(process.env.APP_USERNAME!);
  await pages.login.fillPassword(process.env.APP_PASSWORD!);
  await pages.login.clickLogin();
  await pages.tenants.select(tenant.name);

  // ASSERT (ui)
  await expect(page.getByTestId('tenant-banner')).toHaveText(tenant.name);

  // ASSERT (api)
  // Optional cross-system check via additional client method.

  // TEARDOWN (api)
  await api.tenant.deleteTenant(tenant.id);
});
```

# Quality Gate
- The fixture imports every generated client and every existing page class — none missing, none extra.
- No spec is generated or modified by this skill; it only writes the fixture.
- The fixture contains zero `process.env` reads (all env access is centralized in `config/test-config.ts`).
- `expect` is re-exported so hybrid specs import `test` and `expect` from this file only.
